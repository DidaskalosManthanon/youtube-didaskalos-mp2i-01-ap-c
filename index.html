2.1 — Paradigmes de programmation

Un algorithme est une suite finie d'instructions non ambiguës permettant de résoudre un problème. Un programme est la mise en œuvre concrète d'un algorithme dans un langage de programmation donné.

⚙️
Impératif structuré
On décrit comment faire les calculs : séquences d'instructions, conditions, boucles. L'état de la mémoire évolue au fil de l'exécution.
C — langage de prédilection
λ
Déclaratif fonctionnel
On décrit quoi calculer via des fonctions pures et la récursion. Pas d'effets de bord, l'état mutable est évité autant que possible.
OCaml — fonctionnel par défaut
🗃️
Logique
On exprime des faits et des règles ; le système déduit les réponses. Mentionné uniquement dans le contexte des bases de données (SQL).
SQL (Prolog hors programme)
⚠️ Hors programme : toute théorie générale des paradigmes, la notion de saut inconditionnel (goto).
2.2 — Compilé vs interprété
Chaîne de compilation (C)

Source (.c) → préprocesseur → Objet (.o) → éditeur de liens → Exécutable
Les fichiers .h (interface) déclarent les types et signatures ; les fichiers .c (implémentation) fournissent les définitions.

OCaml — compilé ou interprété

OCaml peut être utilisé en mode interprété (toplevel, ocaml) ou compilé vers du bytecode (ocamlc) ou du code natif (ocamlopt).

2.3 — Représentation des flottants (IEEE 754)

Un flottant double précision (64 bits) est représenté par : 1 bit de signe, 11 bits d'exposant, 52 bits de mantisse. La précision relative est de l'ordre de 10⁻¹⁶.

Conséquences pratiques
  • Ne jamais tester a == b avec des flottants : utiliser |a − b| < ε.
  • L'addition flottante n'est pas associative : (a+b)+c ≠ a+(b+c) en général.
  • Accumulation d'erreurs dans les boucles longues → utiliser des techniques de compensation (Kahan).
2.4 — Terminaison, correction, variant, invariant
Correction partielle

Si l'algorithme s'arrête, alors son résultat est correct. (Ne garantit pas la terminaison.)

Correction totale

Correction partielle ET terminaison garantie.

Variant de boucle

Expression entière, strictement décroissante et minorée par 0 à chaque itération → prouve la terminaison.

Invariant de boucle

Propriété vraie avant la boucle, préservée à chaque itération, et qui permet de conclure la correction après la boucle.
